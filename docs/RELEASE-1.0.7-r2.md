## 1.0.7-r2

> 词库补齐了 330 个原本缺席的高频词，`so`、`would`、`should`、`need` 这些终于有了。
> 另外，打开广场不再需要等 1.3 秒。

### Fixed

- **`/le square` 打开时不再卡 1.3 秒。**

  旧实现把全库聚合结果整片搬进内存，1000 玩家规模实测 1331.6 ms。改用 `EXISTS` 相关子查询加两阶段查询后，
  200 玩家 / 4 万行 47.97 ms → 2.23 ms，1000 玩家 / 20 万行 279.93 ms → 51.18 ms，
  逐页结果与全量查询一致（有真 SQLite 测试钉住）。

  同批还补了 4 个榜单索引。`player_data` 原先只有 `player_name` 一个索引，而三处榜单查询全在
  `ORDER BY ... DESC`，10 万行实测 315.77 ms → 0.65 ms。

- **16 个词教错了意思。** `still` 标成「蒸馏」、`stay` 标成「制止」、`film` 标成「软片」、
  `service` 标成「武装部队的」，玩家学的和例句里用的完全不是一回事。

  根因是词性对齐只判断词性对不对，判断不了义项对不对。已逐个人工订正。

- **两个词的音标丢了元音。** `someone` 生成 `/sʌmwn/`、`understand` 生成 `/ndəˈstænd/`。

- **4 处符号在游戏里显示成豆腐块。** `🔒` 与 `🎓` 在 Minecraft 默认字体栈里没有字形，
  回落到 `unifont` 后必然显示成方框。已换成 BMP 内的 `✖` / `★`。

- **第三方署名一直没打进 JAR。** 打包进去的 `THIRD-PARTY-NOTICES.md` 是 1612 字节的旧副本，
  不含 Tatoeba / NGSL / CMUdict / ECDICT 任何署名。

  而 Maven 只打包 `src/main/resources/`，更新过的版本躺在仓库根从没进过产物。一套含约 2500 句
  Tatoeba（CC BY 2.0 FR，要求署名）的内容一直在零署名状态下分发。已修正并验证产物内含全部声明。

### Added

- **词库从 1025 词扩到 1357 词，三档 487 / 355 / 515。**

  旧词库是从按字母排序的源表里顺序截取的，`advanced` 档 329 个词里 c 开头 143 个、d 开头 125 个，
  合计 81.5%，e 只剩 4 个。结果 NGSL 前 500 的高频词缺席 330 个——玩家学完 1025 词，仍然不会说 `so`。
  现按 NGSL 1.2 词频重排，覆盖率 66.16% → 85.37%（`node docs/vocab/coverage.js` 可复算）。

### Changed

- **词库文件会被自动备份并替换，不用你手动删旧文件。**

  旧版只在词库文件缺失时才释放内置词库，所以跑过旧版的话，升级后读的仍是数据目录里的旧文件，
  新词库对你完全不可见。现在会比对版本号、备份到 `words-backup-v<旧版本>-<时间戳>/` 后替换。

  手工改过词库的话，请从备份目录取回改动再合并。

- **`/lea diagnose` 补进 `/lea help`，输出全部中文化。** 它一直存在、一直能 tab 补全，只是没在 help 里列出来。
  约 30 组硬编码英文迁入 i18n。新增 `/lea diagnose save`，把完整报告写成 txt。

- **两个包源码相同，仅编译目标不同。** 普通包用 paper-api 1.21.4（字节码 major 65），
  支持 MC 1.21.4–1.21.11，需 Java 21+；`-mc26` 包用 paper-api 26.3（major 69），支持 MC 26.1+，需 Java 25+。
  装错包的症状是 `Unsupported class file major version`。

### Known limitations

- **332 个新词的音标未经逐词人工核验。** 它们由 CMUdict 转换而来，那是美式发音，而词库其余部分是英式。
  与原有 1025 词的金标准对比，忽略重音后一致率约 58%–68%，`class` / `dance` / `body` 这类
  英美分歧词仍保留美式读法。

- **约 37% 的新例句含 1–3 个超纲实词**，如 `sumo` / `poverty` / `inherent`。语义与词性已做对齐，
  但未经逐句人工核验。

- **`-mc26` 包的 `api-version` 定在 `26.1` 属推断。** 依据是「26.1–26.3 属同一代 API、只做加法」，
  手上只有 26.3 的 jar，没有 26.1 的真机可跑。在 26.1 上遇到问题请反馈。

### Upgrade notes

- **直接覆盖 JAR，无需卸载。** 配置文件与玩家数据都不会被删。
- **第一次启动会做一次词库备份加替换**，日志会打印备份路径，启动耗时会比平时多一点。
- **数据库改用了 WAL 模式，备份方式变了。** 现在数据库不止 `.db` 一个文件，未合并的事务在 `.db-wal` 里。

  恢复备份请先 checkpoint 再 `.backup`——直接 `cp playerdata.db` 会漏掉未合并的事务；
  只恢复 `.db` 而留下旧 `-wal`，SQLite 会把旧 WAL 重放进刚恢复的库，你想回滚的数据会重新出现且无报错。

  ```bash
  sqlite3 playerdata.db "PRAGMA wal_checkpoint(TRUNCATE);"
  sqlite3 playerdata.db ".backup 'playerdata.db.bak'"
  ```

- **装完怎么确认装对了**：游戏内 `/lea info` 会打印版本、服务端兼容性与数据库类型。
  若版本那行写着 `26.x detected`，说明在 26.x 服务端上装了普通包，换成 `-mc26` 那个。
