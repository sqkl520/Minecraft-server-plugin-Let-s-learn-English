本次发布**两个 JAR**，源码完全相同，只是编译目标不同。**下错包会起不来**：

| 你的服务端 | 下这个 | 需要的 Java |
|---|---|---|
| **MC 1.21.4 – 1.21.11** | `Let.s.Learn.English.-1.0.7.jar` | **Java 21+** |
| **MC 26.1+**（26.2 / 26.3 / 26.4…） | `Let.s.Learn.English.-1.0.7-mc26.jar` | **Java 25+** |

装错包的症状：在 1.21.x 上装 `-mc26` 包，服务端会直接拒绝加载（`api-version: 26.1` 高于服务端）；
在 26.x 上装普通包，可能启动但行为未定义。

用 `/lea info` 可以确认当前装的包与服务端是否匹配。

## 词库重建：1025 → 1357 词，覆盖率 66.16% → 85.37%

这是一次内容层面的根本性修复。

**问题**：原来的三份词库是从按字母排序的源表里**顺序截取**的，不是按难度或词频挑选。
证据是字母分布——`advanced` 档 329 个词里，**c 开头 143 个 + d 开头 125 个 = 81.5%**，
而 e 只剩 4 个、f 只有 1 个；`intermediate` 档 j 之后只剩 3 个词。

后果是 **NGSL（New General Service List，覆盖日常英语 92%）前 500 的高频词缺席 330 个**：

```
as  by  so  would  there  get  other  well  could  work  use  now  into
way  find  after  thing  most  should  need  right  back  mean  even  may
```

这些词一个都不在词库里，反而收了一批低频难词。换句话说：玩家学完 1025 词，
**不会说 "so"、"would"、"should"、"need"**。

**修复**：按 NGSL 1.2 词频排名重排三档 + 补齐 332 个缺失高频词 + 保留"基础词保护"
（`difficulty_level <= 3` 的词不因排名被降档，实测保护 102 个，否则 `boy`/`baby`/`blue`/
`egg`/`milk` 会被挪出 beginner）。

**零移除** —— 已用 `git show HEAD` 逐词核对，原 1025 个词一个不少。
因为玩家进度按词名存在 `word_progress` 表，**你的服升级后玩家进度完全不受影响**。

### ⚠️ 升级必读：词库会被自动替换

旧版本有个坑：插件只在词库文件**缺失**时才释放内置词库。你如果已经跑过旧版，
数据目录里就有旧的 `words/*.yml`，升级后读的仍是旧文件——新词库对你完全不可见。

现在修好了：插件会检测版本号，自动执行**备份 + 替换**：

- 旧词库备份到 `plugins/LetsLearnEnglish/words-backup-v<旧版本>-<时间戳>/`
- 日志会打印备份路径与回滚方法

**如果你手动改过词库**，替换后请从备份目录取回你的改动再合并。

## 广场查询：从"更慢"修成"快 81.7%"

**第一版实现是错的**，这里如实记录。它只把 `LIMIT` 从 `Integer.MAX_VALUE` 改成 28，
但仍然保留了聚合子查询。问题是过滤条件作用在聚合结果上，SQLite 必须先把整张
`word_progress` 聚合完才知道哪些行合格——`LIMIT` 限制不了工作量。而广场每次打开要跑
COUNT + 取页两条语句，等于全表聚合算**两遍**：

| 数据量 | 修复前 | 第一版（错误） | 
|---|---|---|
| 200 玩家 / 4 万行 | 63.0 ms | **102.1 ms（倒退 62%）** |
| 1000 玩家 / 20 万行 | 276.8 ms | **465.1 ms（倒退 68%）** |

改用 `EXISTS` 相关子查询（存在即短路，走 uuid 前缀索引）+ 两阶段查询后：

| 数据量 | 修复前 | 现在 | 变化 |
|---|---|---|---|
| 200 玩家 / 4 万行 | 47.97 ms | **2.23 ms** | **-95.4%** |
| 1000 玩家 / 20 万行 | 279.93 ms | **51.18 ms** | **-81.7%** |

逐页拼接结果与全量查询**逐行一致、无重复无遗漏**（有真 SQLite 测试钉住）。

### 其他性能项

- **4 个榜单索引**：`player_data` 原先只有 `player_name` 一个索引，而三处榜单全在
  `ORDER BY ... DESC`。实测 10 万行 **315.77 ms → 0.65 ms**
- **SQLite 开启 WAL**：`journal_mode=WAL` + `synchronous=NORMAL`，写不再阻塞读

> ⚠️ **WAL 改变了备份方式**：数据库现在不止 `.db` 一个文件，未合并的事务在 `.db-wal` 里。
> 恢复备份时**必须先删掉 `playerdata.db-wal` / `-shm`**，否则旧 WAL 会被重放进刚恢复的库，
> 你想回滚的数据会重新出现且无报错。README 与 DEPLOYMENT_WIKI 已更新为
> `PRAGMA wal_checkpoint(TRUNCATE)` + `.backup` 的正确做法。

## AI 对话

新增 `ai-chat.thinking-mode` 与 `ai-chat.reasoning-effort` 两个配置项，
**默认值均为「一个字节都不多发」——线上请求体与本功能加入前逐字节一致**。

为什么做成配置而不是直接改：DeepSeek V4 系列据称默认开启思考模式，而思考消耗的也是
`max_tokens`，本插件对话路径只有 128，一旦上游默认思考可能把预算吃光后返回空内容
——玩家看到 AI 不说话、日志里却是 200 成功，是最难排查的静默失败。

但该行为的 API 形状**未能从官方文档核实**，且不同来源给出的替代模型名互相矛盾
（`deepseek-flash` vs `deepseek-v4-flash`），所以不擅自改默认值，交给服主按需开启。

## 已知限制（如实说明）

1. **332 个新词的音标未经逐词人工核验**。它们由 CMUdict 转换而来——那是**美式**发音，
   而词库其余部分是**英式**。转换器做了英式映射，但 `æ/ɑː` 这类英美分歧词
   （`class`/`dance`/`body`）仍保留美式读法；与原有 1025 词的金标准对比，
   忽略重音后一致率约 58%–68%
2. **例句含超纲词**：约 37% 的新例句有 1–3 个超出词库范围的实词
   （`sumo`/`poverty`/`inherent`/`sanction` 等）。语义与词性已做对齐，但未经逐句人工核验
3. **`-mc26` 包的 `api-version` 定在 `26.1` 属推断**：依据是「26.1–26.3 属同一代 API、
   只做加法」。手上只有 26.3 的 jar，没有 26.1 的真机可跑。若你在 26.1 上遇到问题请反馈

发现任何问题都可以直接改 `plugins/LetsLearnEnglish/words/*.yml` 后 `/lea reload`。
